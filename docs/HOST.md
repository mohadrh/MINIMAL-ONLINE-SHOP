# انتقال سایت روی هاست

راهنمای قدم‌به‌قدم. طراحی سایت **هیچ تغییری نمی‌کند** — خروجی
همان فایل‌های HTML و CSS است و روی هر سروری یکسان دیده می‌شود.

---

## قبل از شروع: چیدمان دامنه

روی یک هاست دو چیز داریم و نباید قاطی شوند:

```
yourdomain.ir            ← سایت فونیکس (فایل‌های ایستا)
panel.yourdomain.ir      ← وردپرس و ووکامرس (پنل مدیریت)
```

**چرا وردپرس روی زیردامنه؟** اگر وردپرس را در ریشه نصب کنید، با
فایل‌های سایت تداخل می‌کند — هر دو می‌خواهند `index.php` یا
`index.html` ریشه باشند و نتیجه‌اش سایتِ نصفه است. پلن شما ۲۰
زیردامنه دارد؛ یکی‌اش را برای پنل بگذارید.

مشتری هیچ‌وقت `panel.` را نمی‌بیند مگر لحظه‌ی پرداخت.

> ⚠ **اسمش را `shop` نگذارید.**
>
> دایرکت‌ادمین زیردامنه را داخلِ `public_html` می‌سازد، یعنی
> `shop.yourdomain.ir` می‌شود پوشه‌ی `public_html/shop`. ولی
> خودِ سایت هم صفحه‌ی `/shop/` دارد و همان‌جا `index.html` خودش
> را گذاشته. یکی روی دیگری می‌افتد و بسته به ترتیب آپلود، یا
> صفحه‌ی فروشگاهِ سایت گم می‌شود یا وردپرس بالا نمی‌آید.
>
> اسم‌هایی که با هیچ صفحه‌ای تصادم ندارند: `panel`، `api`، `my`.
> اسم‌هایی که **دارند** — چون صفحه‌ی سایت‌اند: `shop`، `products`،
> `blog`، `account`، `cart`، `checkout`، `games`، `ai`، `club`،
> `login`، `social`، `numbers`، `giftcards`، `creative`،
> `education`، `gaming`، `about`، `contact`، `faq`، `rules`،
> `guide`، `track`، `reseller`، `careers`، `product`، `giftcard`،
> `complaint`.

---

## گام ۱ — بیلد

روی کامپیوتر خودتان، در پوشه‌ی پروژه:

```bash
npm run build:host
```

> ⚠ حتماً `build:host` و نه `build`.
>
> نسخه‌ی گیت‌هاب همه‌ی آدرس‌ها را با پیشوند `/MINIMAL-ONLINE-SHOP`
> می‌سازد چون آن‌جا سایت زیر یک زیرمسیر است. اگر همان را آپلود
> کنید، مرورگر دنبال فایل‌هایی می‌گردد که وجود ندارند و صفحه
> **سفید و بی‌استایل** بالا می‌آید. این دستور همان بیلد را بدون
> پیشوند می‌سازد.

بعد از تمام شدن، پوشه‌ی `out/` ساخته می‌شود — حدود ۲۱ مگابایت.

---

## گام ۲ — آپلود

۱. وارد پنل هاست شوید (cPanel یا DirectAdmin)
۲. **File Manager** را باز کنید
۳. وارد پوشه‌ی `public_html` شوید
۴. اگر چیزی داخلش هست (مثل `index.html` پیش‌فرض هاست)، پاکش کنید
۵. **محتویات** پوشه‌ی `out` را آپلود کنید

> ⚠ خودِ پوشه‌ی `out` را آپلود نکنید — **داخلش** را.
>
> اگر `out` را بگذارید، سایت روی `yourdomain.ir/out/` می‌افتد.

**ساده‌ترین راه:** پوشه‌ی `out` را روی کامپیوتر zip کنید، فایل zip
را آپلود کنید، در File Manager روی آن راست‌کلیک و **Extract**
بزنید، بعد فایل‌ها را از پوشه‌ی `out` به `public_html` منتقل کنید.

---

## گام ۳ — فایل مخفی

در `out/` یک فایل به نام `.htaccess` هست که HTTPS اجباری، فشرده‌سازی
و کش را تنظیم می‌کند.

در File Manager از تنظیمات، **Show Hidden Files** را روشن کنید تا
ببینیدش. حتماً باید همراه بقیه آپلود شود.

---

## گام ۴ — SSL

از پنل هاست، بخش **SSL** یا **Let's Encrypt**، گواهی رایگان را
برای دامنه فعال کنید.

بدون این:
- مرورگر به بازدیدکننده هشدار «ناامن» می‌دهد
- هیچ درگاه پرداختی وصل نمی‌شود
- فایل `.htaccess` مدام ریدایرکت می‌کند و سایت لوپ می‌خورد

---

## گام ۵ — امتحان

سایت را باز کنید و این‌ها را چک کنید:

- [ ] صفحه‌ی اصلی با تمام رنگ‌ها و فونت درست بالا می‌آید
- [ ] روی یک محصول کلیک کنید — صفحه‌اش باز شود
- [ ] آدرس `yourdomain.ir/shop/` مستقیم در مرورگر کار کند
- [ ] یک آدرس الکی مثل `yourdomain.ir/xyz` صفحه‌ی ۴۰۴ خودمان را نشان دهد
- [ ] روی موبایل هم باز کنید

اگر صفحه **سفید و بی‌استایل** بود، یعنی با `npm run build` بیلد
شده نه `build:host`. دوباره بسازید.

---

## بعد از هر تغییر

هر بار چیزی در سایت عوض شد:

```bash
npm run build:host
```

و دوباره محتویات `out/` را آپلود کنید.

> اگر می‌خواهید این کار خودکار شود، می‌شود با FTP از GitHub Actions
> آپلود کرد — بگویید تا تنظیمش کنم.

---

## هر دو جا با هم

می‌توانید هم‌زمان روی گیت‌هاب و هم روی هاست خودتان داشته باشید:

| کجا | با چه دستوری | برای چه |
|---|---|---|
| گیت‌هاب | `npm run build` | نسخه‌ی آزمایشی، نشان دادن به دیگران |
| هاست خودتان | `npm run build:host` | سایت اصلی |

فقط حواستان باشد کدام را کجا آپلود می‌کنید.
