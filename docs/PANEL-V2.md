# پنلِ فونیکس — نسخه‌ی ۲

> نقشه‌ی بازسازیِ کاملِ پنل. هر مرحله که تمام شد، همین‌جا تیک
> می‌خورد تا اگر جلسه‌ای قطع شد، از همان‌جا ادامه دهیم.

---

## چرا بازسازی، نه اصلاح

کارفرما گفت پنلِ فعلی «خیلی به هم ریخته» است و آدم گیج می‌شود. حق
دارد، و مشکل از ظاهر نیست، از ساختار است:

| مشکلِ نسخه‌ی ۱ | نتیجه |
|---|---|
| محصول در دو جا ویرایش می‌شود: صفحه‌ی ووکامرس + تبِ فونیکس | نمی‌دانی هر چیز را کجا عوض کنی |
| فهرست‌ها (ویژگی، سوال، ورودیِ لازم) با **JSON** نوشته می‌شوند | یک ویرگولِ جاافتاده = ذخیره نمی‌شود |
| قیمت فقط دو منبع دارد: دستی یا «دلار × نرخ» | نمی‌شود گفت «قیمتِ این یکی را از فلان API بخوان» |
| هر صفحه فرمِ PHPِ جدا با رفرشِ کامل | کُند، و هر ذخیره صفحه را از نو می‌سازد |
| فقط حالتِ روشن | پنلی که روزی ده بار باز می‌شود |

---

## معماری

```
wp-plugin/phoenix-bridge/
  includes/
    api/            ← REST: همه‌ی داده‌ی پنل از این‌جا
      guard.php     ← نگهبانِ مشترک: قابلیت + nonce + محدودیتِ نرخ
      products.php  ← فهرست، خواندن، نوشتنِ محصول با ساختارِ خودمان
      sources.php   ← منابعِ قیمت: تعریف، تست، خواندن
      pricing.php   ← پیش‌نمایش و به‌روزرسانیِ قیمت
      ...
    sources/        ← انواعِ منبعِ قیمت
      rate.php      ← نرخِ ارز از چند صرافی (همان نسخه‌ی ۱)
      http.php      ← APIِ سفارشی: نشانی، مسیرِ عدد، واحد، کلید
    secrets.php     ← رمزنگاریِ کلیدهای API در پایگاه داده
  admin/
    app.js          ← پنل، بدونِ ابزارِ بیلد
    screens/*.js    ← یک فایل برای هر صفحه
    app.css         ← توکن‌های رنگ، حالتِ روشن و تاریک
```

### ⚠ چرا بدونِ ابزارِ بیلد (React/Vite/…)

افزونه باید با یک زیپ نصب شود. ابزارِ بیلد یعنی:

- هر تغییر باید اول روی کامپیوتر بیلد شود، بعد زیپ — یک قدمِ اضافه
  که روزی فراموش می‌شود و زیپِ کهنه منتشر می‌شود
- صدها بسته‌ی npm داخلِ زنجیره‌ی تأمینِ پنلی که به پول دسترسی دارد

جاوااسکریپتِ امروزیِ مرورگر (ماژول، `fetch`، کلاس) برای این پنل
کافی است. فایل همان چیزی است که اجرا می‌شود.

## صفحه‌ها

**۱ داشبورد** — یک نگاه، کلِ وضعیت
- کاشی‌های وضعیت: نرخ، منابعِ سالم، محصولاتِ دستِ موتور، صفِ تحویل،
  تخفیفِ فعال، سلامتِ کلی
- **هشدارهای هوشمند**: فقط وقتی کاری لازم است — منبعِ خوابیده، نرخِ
  کهنه، محصولی که کفِ قیمت تخفیفش را خورده، کارِ ناموفق
- **پیشنهادها**: کارِ بعدی — «۱۲ محصول هنوز قیمتِ تمام‌شده ندارند»
- نمودارِ نرخ و آخرین تغییرات

**۲ محصولات** — جایگزینِ کاملِ ویرایشگرِ ووکامرس برای کارِ روزمره

فهرست: جست‌وجو، فیلتر (دسته، منبعِ قیمت، وضعیت، «بدونِ قیمتِ
تمام‌شده»)، ستونِ قیمتِ الان و قیمتِ تمام‌شده و سود.

ویرایشگرِ هر محصول، با تب:

| تب | محتوا |
|---|---|
| اصلی | عنوان، عنوانِ انگلیسی، برند، دسته، تگ‌ها، وضعیت |
| پلن‌ها | هر پلن یک ردیف: برچسب، راهنما، موجودی، پیش‌فرض، ترتیب (کشیدنی) |
| **قیمت‌گذاری** | منبع و تنظیمات — برای کلِ محصول، یا جدا برای هر پلن |
| رسانه | تصویرِ کارت، لوگو، کاور، رنگِ شاخص — با پیش‌نمایش |
| محتوا | توضیحِ کوتاه و بلند، ویژگی‌ها، نکته‌ها، سوالات، پلتفرم‌ها |
| تحویل | روشِ تحویل، ورودی‌های لازم از مشتری، زمان، گارانتی |

⚠ **هیچ JSONی جلوی ادمین نیست.** هر فهرست یک ویرایشگرِ ردیفی است:
افزودن، حذف، جابه‌جایی.

**۳ منابعِ قیمت** — جدید
- **نرخِ ارز**: چند صرافی، سیاستِ انتخاب (کمترین/میانه)، فیلترِ پرت
- **APIِ سفارشی**: هر تعداد که بخواهی
  - نشانی، روش (GET/POST)، مسیرِ عدد در پاسخ، واحد (دلار/تومان/ریال)
  - کلید و هدرها — **رمزنگاری‌شده** ذخیره، هیچ‌وقت به مرورگر برنمی‌گردد
  - عمرِ کش، بازه‌ی معقول
  - **دکمه‌ی آزمایش**: پاسخِ خام، عددِ استخراج‌شده، زمانِ پاسخ

**۴ حاشیه‌ها** — نمایه‌های سود (کل، دسته) با پیش‌نمایشِ زنده

**۵ تخفیف‌ها** — قاعده‌های گروهی و کدهای اختصاصی

**۶ صفِ تحویل** — **۷ تاریخچه** — **۸ تنظیمات** (ظاهر، موتور، کرون، امنیت)

## قیمت‌گذاری برای هر محصول و هر پلن

هر پلن یکی از این منابع را دارد (یا از محصول ارث می‌برد):

| منبع | قیمت از کجا |
|---|---|
| **دستی** | عددی که خودت می‌نویسی. موتور دست نمی‌زند. |
| **هزینه‌ی دلاری × نرخ** | قیمتِ تمام‌شده به دلار، ضربدر نرخِ ارز، به‌علاوه‌ی سود |
| **هزینه‌ی تومانی** | قیمتِ تمام‌شده به تومان، به‌علاوه‌ی سود |
| **API** | عدد از یک منبعِ تعریف‌شده، با ضریب و واحد، به‌علاوه‌ی سود |

و روی همه‌شان:
- **سود**: ارث از دسته/کل، یا اختصاصیِ همین محصول
- **رُند و عددِ جذاب**: ارث یا اختصاصی
- **قفل**: موتور دست نزند
- **کفِ قیمت**: همیشه، و آخرین حرف

⚠ **پیش‌نمایش همیشه جلوی چشم است** — پیش از ذخیره: پایه چند، سود چند،
تخفیف چند، نهایی چند، و فرقش با قیمتِ الانِ سایت.

## به‌روزرسانیِ قیمت

| کِی | چطور |
|---|---|
| هر ساعت | کرونِ سرور، همه‌ی منابع |
| سرِ خرید | اگر قیمتِ سبد از *X* دقیقه کهنه‌تر است، دوباره حساب می‌شود |
| دستی | دکمه روی هر محصول، هر منبع، یا همه |

⚠ **سرِ خرید، قیمت بی‌صدا عوض نمی‌شود.** اگر بینِ سبد و پرداخت بالا
رفته باشد، پیش از پرداخت به مشتری گفته می‌شود. اگر پایین آمده باشد،
قیمتِ پایین‌تر بی‌صدا اعمال می‌شود.

## امنیت

| خطر | کار |
|---|---|
| درخواستِ بی‌اجازه | هر مسیرِ REST: `manage_woocommerce` + nonceِ `wp_rest` |
| لو رفتنِ کلیدِ API | رمزنگاری با کلیدِ مشتق از `AUTH_KEY` وردپرس؛ به مرورگر فقط «تنظیم شده / نشده» |
| SSRF از منبعِ سفارشی | فقط https، ردِ IPِ داخلی، سقفِ زمان و حجم |
| سوءاستفاده از دکمه‌ی آزمایش | محدودیتِ دفعات برای هر کاربر |
| ورودیِ خراب | اسکیمای ورودی روی هر مسیر؛ هر رشته sanitize، هر عدد محدود |
| XSS در پنل | پنل متن را با `textContent` می‌گذارد، هیچ‌جا `innerHTML`ِ داده |
| تغییرِ بی‌رد | هر نوشتن در دفترِ رویداد |

## ظاهر

- **روشن / تاریک / سیستم** — برای هر کاربر جدا ذخیره می‌شود
- نوارِ کناری با منو، نوارِ بالا با جست‌وجو و چیپِ نرخِ زنده
- کاشی‌های وضعیت با نشانِ رنگی **و** متنی (رنگ به‌تنهایی حاملِ معنا نیست)
- فونتِ وزیرمتن، **داخلِ خودِ افزونه** — نه از گوگل، که از ایران گاهی
  باز نمی‌شود و پنل بی‌فونت می‌ماند

### قیمت از چند منبع (۱٫۳٫۰)

برای کلِ محصول یا هر پلن: چند منبع (API یا عددِ دستی، دلار/تومان/ریال)،
الگوی انتخاب (کمترین، میانه، میانگین، اولین پاسخ، یا یک منبعِ مشخص)،
بعد همان موتور: حاشیه ← رُند ← تخفیف ← کف. هر ساعت خودکار.

دو محافظ: اگر هیچ منبعی جواب ندهد قیمتِ قبلی می‌ماند؛ جهشِ بیش از
سقف (پیش‌فرض ۳۰٪) نگه داشته می‌شود تا ادمین تأیید کند.

کلیدِ API در «اتصال‌ها» (تنظیماتِ افزونه، رمزنگاری‌شده با نمکِ
wp-config) — هیچ‌وقت در متای محصول، هیچ‌وقت به مرورگر.
پیکربندیِ منابع در متای جدای ‎_phoenix_sources‎، نه در ‎_phoenix‎ که
فیلدهای نمایشی‌اش بیرون می‌رود.

شده، در نسخه‌ی ۲ بی‌دستکاری باز می‌شود.
