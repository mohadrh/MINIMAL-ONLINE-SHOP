# اعلانِ خرید در تلگرام — و API برای رباتِ خودتان

> Phoenix Account ۰٫۹٫۰ (با Phoenix Bridge ۱٫۷٫۰) — پیشخوان ← «مشتریان» ← «اعلان در تلگرام».

هر خرید از سایت، با جزئیات، همان لحظه در تلگرامِ شما. اگر رباتِ خودتان یا سیستمِ دیگری
دارید، همان اطلاعات با یک API امضاشده به آن هم می‌رسد.

## نمونه‌ی پیام

```
🛒 سفارشِ تازه — پرداخت شد
سفارشِ #۱۲۰۴ · ۱٬۲۹۰٬۰۰۰ تومان
👤 علی رضایی · ۰۹۱۲۱۲۳۴۵۶۷ · ali@example.com

• اسپاتیفای پریمیوم — یک‌ماهه — ۵۲۰٬۰۰۰ تومان
• گیفت‌کارت ×۲ — ۷۷۰٬۰۰۰ تومان

💳 زرین‌پال · کدِ پیگیری 123456789
باز کردن در پنل
```

## راه‌اندازی

1. **ربات:** با ‎@BotFather‎ یک ربات بسازید، توکنش را در «منابعِ قیمت ← اتصال‌ها» بگذارید
   (docs/TELEGRAM.md). در «اعلان در تلگرام» ← «توکنِ ربات» انتخابش کنید ← ذخیره ←
   **وصل کردنِ ربات**.
2. **گیرنده با کد** (ساده‌ترین): «اتصالِ گفتگو با کد»، و تا ۱۵ دقیقه یکی از این‌ها:
   - **گفتگوی خودتان:** پیوندِ نشان‌داده‌شده را باز کنید و Start را بزنید.
   - **گروهِ فروش:** ربات را عضوِ گروه کنید و متنِ «برای گروه» را در گروه بفرستید.
   - **کانال:** ربات را مدیرِ کانال کنید و کد را در کانال بفرستید.

   بعد «تازه کن» ← گیرنده در فهرست است.
3. **اعلان‌ها روشن** ← رویدادها ← **ذخیره** ← **ارسالِ آزمایشی**.

## با رباتی که برنامه‌ی خودش را دارد (مثلاً رباتِ فروش)

«وصل کردنِ ربات» را نزنید — وبهوکش را برمی‌دارد و ربات از کار می‌افتد. فقط توکن را
انتخاب کنید و گیرنده را **دستی** بنویسید:
- گفتگوی خصوصی: شناسه‌ی عددی‌تان را ‎@userinfobot‎ می‌دهد. پیش از آن ربات را Start کنید —
  ربات به کسی که بازش نکرده پیام نمی‌دهد.
- گروه: شناسه با ‎-‎ شروع می‌شود (برنامه‌نویسِ ربات از پیام‌های گروه می‌بیند).
- کانالِ عمومی: ‎@نامِ‌کانال‎ (ربات باید مدیرِ کانال باشد).

## چه چیزی می‌آید

| رویداد | پیش‌فرض |
|---|---|
| سفارشِ پرداخت‌شده | روشن |
| سفارشِ منتظرِ تأییدِ پرداخت (کارت‌به‌کارت) | روشن |
| مشتری اطلاعاتِ تحویل را اصلاح کرد | روشن |
| سفارشِ ثبت‌شده، هنوز پرداخت‌نشده | خاموش |
| پیامِ تازه‌ی مشتری در تیکت | خاموش |
| گفتگوی تازه در چتِ آنلاین | خاموش |

هر رویداد برای هر گیرنده **یک بار** — «در حال انجام» و «تکمیل‌شده»ی یک سفارش دو پیام نمی‌شوند.

**حریمِ خصوصی:** شماره و ایمیلِ مشتری با یک کلید خاموش می‌شوند؛ اطلاعاتی که مشتری برای
تحویل وارد کرده (مثلاً ایمیلِ اکانت) پیش‌فرض خاموش است و هر ورودیِ شبیهِ رمز (رمز، پسورد،
PIN، کدِ تأیید) همیشه `••••••` می‌رود. کد و پسوردِ تحویل‌شده **هیچ‌وقت** در اعلان نیست.

**اگر نرسید:** پرداختِ مشتری هیچ‌وقت منتظرِ تلگرام نمی‌ماند — پیام در پس‌زمینه می‌رود و
اگر نرسید تا شش بار دوباره (از ۱ دقیقه تا ۳ ساعت). در «آخرین اعلان‌ها» وضعیت و دلیل
هست و «دوباره». اگر رباتی از گروه بیرون شده باشد همان بار «نرسید» می‌شود. هاستی که به
تلگرام نمی‌رسد: همان «واسطه‌ی تلگرام» در docs/TELEGRAM.md.

## API — برای برنامه‌نویسِ رباتِ شما

در «اعلان در تلگرام» ← «API برای برنامه‌ی دیگر»: روشن، نشانیِ https، ذخیره. برای هر
رویداد یک درخواست:

```
POST https://your-bot.example.com/phoenix
Content-Type: application/json; charset=utf-8
X-Phoenix-Event:     order_paid
X-Phoenix-Delivery:  1287
X-Phoenix-Timestamp: 1791234567
X-Phoenix-Signature: sha256=5b94d0bb…
```

```json
{
  "event": "order_paid",
  "delivery": 1287,
  "sent_at": "2026-10-06T10:20:31+00:00",
  "site": "panel.phonixmarket.com",
  "data": {
    "id": 1204, "number": "1204", "status": "processing", "total": 1290000, "currency": "IRT",
    "created": "2026-10-06T13:49:02+03:30", "paid": "2026-10-06T13:50:11+03:30",
    "payment":  { "method": "زرین‌پال", "transaction_id": "123456789", "is_paid": true },
    "customer": { "name": "علی رضایی", "phone": "09121234567", "email": "ali@example.com" },
    "items": [
      { "item_id": 88, "product_id": 512, "name": "اسپاتیفای پریمیوم — یک‌ماهه", "qty": 1, "total": 520000,
        "inputs": [ { "key": "ایمیلِ اکانت", "value": "x@y.com" }, { "key": "رمزِ اکانت", "value": "••••••" } ] }
    ],
    "admin_url": "https://panel.phonixmarket.com/wp-admin/admin.php?page=phoenix-customers#/orders/1204"
  }
}
```

- رویدادها: `order_paid`، `order_on_hold`، `order_new`، `input_fixed`، `ticket`، `chat`.
  برای `ticket`: ‎`ticket_id, subject, phone, excerpt, admin_url`‎؛ برای `chat`:
  ‎`chat_id, agent, phone, page, excerpt, admin_url`‎.
- `phone`/`email` و `inputs` طبقِ همان کلیدهای حریمِ خصوصی.
- **پاسخِ ۲xx یعنی رسید.** ۴۰۸، ۴۲۹، ۵xx یا خطای شبکه → دوباره (تا شش بار)؛ بقیه‌ی ۴xx
  → «نرسید». تغییرِ مسیر (۳xx) دنبال نمی‌شود. ظرفِ ۱۰ ثانیه جواب بدهید.
- ممکن است یک رویداد **دو بار** برسد (شبکه بعد از رسیدن قطع شد) — با `delivery` تکراری را کنار بگذارید.

### بررسیِ امضا — حتماً

امضا = ‎`sha256=` + HMAC-SHA256(رمز، `{X-Phoenix-Timestamp}.{بدنه‌ی خام}`)‎. رمز در همان کارت
(«رمزِ امضا»). درخواستی که امضایش نمی‌خواند یا زمانش بیش از ۵ دقیقه فاصله دارد را رد کنید.

```python
import hmac, hashlib, time

def verify(secret: str, headers, raw_body: bytes) -> bool:
    ts = headers.get("X-Phoenix-Timestamp", "")
    sig = headers.get("X-Phoenix-Signature", "")
    if not ts.isdigit() or abs(time.time() - int(ts)) > 300:
        return False
    mac = hmac.new(secret.encode(), f"{ts}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(sig, "sha256=" + mac)
```

```js
import crypto from 'node:crypto';

export function verify(secret, headers, rawBody /* Buffer */) {
  const ts = headers['x-phoenix-timestamp'] || '';
  const sig = headers['x-phoenix-signature'] || '';
  if (!/^\d+$/.test(ts) || Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;
  const mac = 'sha256=' + crypto.createHmac('sha256', secret).update(ts + '.').update(rawBody).digest('hex');
  return sig.length === mac.length && crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(mac));
}
```

⚠ امضا را روی **بدنه‌ی خام** حساب کنید، نه JSONی که دوباره ساخته‌اید.
⚠ رمز فقط روی سرورِ ربات؛ اگر لو رفت، «رمزِ تازه».
