# بالا آوردنِ سایت روی phonixmarket.com — امروز

> این سند برای **یک ساعتِ اول** است: سایت روی دامنه‌ی خودت، زنده و
> قابلِ دیدن. وردپرس و پرداخت در سندِ جداست و امروز نیست — دلیلش
> ته همین صفحه نوشته شده.

---

## اول از همه: یک چیز می‌تواند کلِ ساعت را خراب کند

**DNS.**

اگر دامنه‌ی `phonixmarket.com` هنوز به نیم‌سرورهای نت‌افراز وصل
نشده، بقیه‌ی این مراحل را می‌شود در بیست دقیقه انجام داد ولی سایت
تا **۲ تا ۲۴ ساعت** بالا نمی‌آید — و هیچ کاری از دستِ ما
برنمی‌آید، آن تأخیر مالِ شبکه است نه مالِ ما.

پس **همین الان، پیش از هر کارِ دیگر** این را چک کن:

```bash
nslookup phonixmarket.com
```

- اگر IPِ سرورِ نت‌افراز را برگرداند → عالی، برو گامِ ۱
- اگر چیزی برنگرداند یا IPِ جای دیگری بدهد → **اول برو نیم‌سرورها
  را در پنلِ ثبت‌کننده‌ی دامنه عوض کن**، بعد بقیه‌ی کارها را انجام
  بده. تا وقتی منتظری، همه‌ی گام‌های زیر را می‌شود جلو برد؛ فقط
  نتیجه دیرتر دیده می‌شود.

نیم‌سرورها را نت‌افراز در ایمیلِ خوش‌آمدِ هاست فرستاده، چیزی شبیه
`ns1.netafraz.com`.

---

## گام ۱ — بیلد (۲ دقیقه)

در پوشه‌ی پروژه:

```bash
npm run build:host
```

⚠ حتماً `build:host` و نه `build`. نسخه‌ی گیت‌هاب همه‌ی آدرس‌ها را
با پیشوندِ `/MINIMAL-ONLINE-SHOP` می‌سازد؛ اگر آن را آپلود کنی
سایت **سفید و بی‌استایل** بالا می‌آید.

خروجی: پوشه‌ی `out/` — حدود **۳۶ مگابایت** و **۳۸۵ فایل**.

---

## گام ۲ — فشرده کن (۱ دقیقه)

⚠ **۳۸۵ فایل را تک‌تک آپلود نکن.** با File Managerِ دایرکت‌ادمین
این کار نیم‌ساعت طول می‌کشد و وسطش قطع می‌شود.

روی ویندوز، داخلِ پوشه‌ی `out` برو، همه را انتخاب کن
(`Ctrl+A`)، راست‌کلیک → Send to → Compressed (zipped) folder.

⚠ **محتویاتِ `out` را zip کن، نه خودِ پوشه‌ی `out` را.** اگر پوشه
را zip کنی، بعد از Extract همه‌چیز داخلِ `public_html/out/` می‌افتد
و سایت روی `phonixmarket.com/out/` بالا می‌آید.

---

## گام ۳ — آپلود (۵ تا ۱۵ دقیقه)

۱. وارد دایرکت‌ادمین شو
۲. **File Manager** → پوشه‌ی `public_html`
۳. هرچه داخلش هست پاک کن (فایلِ `index.html`ِ پیش‌فرضِ هاست،
   `default.html`، پوشه‌ی `cgi-bin` را کار نداشته باش)
۴. فایلِ zip را آپلود کن
۵. راست‌کلیک رویش → **Extract**
۶. فایلِ zip را بعدش پاک کن

---

## گام ۴ — فایلِ مخفی (۱ دقیقه)

در `out/` فایلی به نامِ `.htaccess` هست که HTTPSِ اجباری،
فشرده‌سازی و کش را تنظیم می‌کند. چون با نقطه شروع می‌شود، File
Manager پیش‌فرض نشانش نمی‌دهد.

از تنظیماتِ File Manager **Show Hidden Files** را روشن کن و مطمئن
شو `.htaccess` در `public_html` هست.

اگر نبود، از `out/.htaccess` جداگانه آپلودش کن.

---

## گام ۵ — SSL (۵ دقیقه)

دایرکت‌ادمین → **SSL Certificates** → Let's Encrypt → برای
`phonixmarket.com` و `www.phonixmarket.com` بگیر.

⚠ این اختیاری نیست:

- بدونش مرورگر به هر بازدیدکننده هشدارِ «ناامن» می‌دهد
- هیچ درگاهِ پرداختی روی سایتِ بدونِ SSL وصل نمی‌شود
- `.htaccess` به HTTPS ریدایرکت می‌کند و بدونِ گواهی، سایت
  **لوپ می‌خورد** و اصلاً بالا نمی‌آید

پس اگر بعد از آپلود سایت لوپ خورد، دنبالِ باگ نگرد — SSL هنوز
فعال نشده.

---

## گام ۶ — امتحان (۵ دقیقه)

- [ ] `phonixmarket.com` با رنگ و فونتِ درست بالا می‌آید
- [ ] قفلِ سبزِ HTTPS هست
- [ ] روی یک محصول کلیک کن — صفحه‌اش باز شود
- [ ] `phonixmarket.com/shop/` را **مستقیم در نوارِ آدرس** بزن
- [ ] `phonixmarket.com/contact/` باز شود
- [ ] یک آدرسِ الکی مثل `phonixmarket.com/xyz` صفحه‌ی ۴۰۴ِ خودمان
      را بدهد، نه ۴۰۴ِ هاست
- [ ] با موبایل هم باز کن

**اگر سفید و بی‌استایل بود** → با `npm run build` ساخته شده نه
`build:host`. دوباره بساز.

**اگر `/shop/` کار نکرد ولی صفحه‌ی اصلی کار کرد** → `.htaccess`
آپلود نشده.

## تا این‌جا چه داری و چه نداری

| هست | نیست |
|---|---|
| همه‌ی صفحه‌ها، محصولات، قیمت‌ها | پرداختِ واقعی |
| جست‌وجو، فیلتر، سبدِ خرید | ثبتِ سفارش در پایگاه داده |
| چتِ آنلاین با پاسخ‌های آماده | پنلِ کاربریِ واقعی |
| تماس با ما، پیگیری با کدِ نمونه | پیگیریِ سفارشِ واقعی |

یعنی **ویترین کامل است و صندوق هنوز نه**. مشتری می‌تواند همه‌چیز
را ببیند و سبد بچیند، ولی سرِ پرداخت باید به تلگرام هدایت شود.

برای امروز این کافی است و اتفاقاً بد هم نیست: خیلی از فروشگاه‌های
این بازار همین‌طور شروع می‌کنند و سفارش را دستی در تلگرام
می‌گیرند.

---

## چرا وردپرس امروز نه

موتورِ قیمت و پنلش آماده است (`wp-plugin/phoenix-bridge`، ۵۸ تست).
ولی تا زنده شدنش این‌ها لازم است و هیچ‌کدام در یک ساعت جا نمی‌شوند:

| کار | زمانِ واقعی |
|---|---|
| نصبِ وردپرس روی زیردامنه‌ی `panel.` | ۲۰ دقیقه |
| نصب و راه‌اندازیِ ووکامرس | ۳۰ دقیقه |
| وارد کردنِ ۳۶ محصول با قیمتِ تمام‌شده | ۲ تا ۳ ساعت |
| گرفتنِ درگاهِ پرداخت (زرین‌پال/آیدی‌پی) | **۱ تا ۷ روزِ کاری** — نیاز به نماد و مدارک |
| تستِ سفارشِ واقعی سرتاسر | ۱ ساعت |

آن ردیفِ پررنگ دستِ ما نیست. درگاه بدونِ نمادِ اعتماد یا حداقل
مدارکِ هویتی وصل نمی‌شود، و آن فرآیند چند روز طول می‌کشد.

⚠ **پس پیشنهادم:** امروز ویترین را زنده کن، و **همین امروز**
پرونده‌ی درگاه را هم باز کن — چون آن طولانی‌ترین انتظار است و هرچه
دیرتر شروع شود، کلِ فروشگاه دیرتر واقعی می‌شود.

---

## ترتیبِ درستِ روزهای بعد

۱. **امروز** — ویترین روی دامنه (این سند) + شروعِ پرونده‌ی درگاه
۲. **فردا** — وردپرس روی `panel.phonixmarket.com` + ووکامرس +
   نصبِ `phoenix-bridge` (راهنما: `docs/BACKEND.md`)
۳. **روزِ سوم** — وارد کردنِ محصولات با قیمتِ تمام‌شده، تنظیمِ
   حاشیه، روشن کردنِ موتورِ قیمت
۴. **وقتی درگاه آمد** — وصل کردن و تستِ سفارشِ واقعی
۵. **بعد از یکی‌دو ماه آمار** — روشن کردنِ خریدِ خودکار

## اگر جایی گیر کردی

| نشانه | علت |
|---|---|
| سایت سفید و بی‌استایل | با `build` ساخته شده نه `build:host` |
| لوپِ بی‌پایانِ ریدایرکت | SSL هنوز فعال نیست |
| صفحه‌ی اصلی کار می‌کند، بقیه ۴۰۴ | `.htaccess` آپلود نشده |
| سایت روی `/out/` افتاده | خودِ پوشه zip شده بود، نه محتویاتش |
| دامنه اصلاً باز نمی‌شود | DNS هنوز نرسیده — صبر، نه تغییرِ کد |
