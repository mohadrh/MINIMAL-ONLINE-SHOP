# اتصال بک‌اند — وردپرس و ووکامرس

این سند می‌گوید چه چیزی ساخته شده، چه چیزی هنوز لازم است، و
دقیقاً چه کار باید کرد تا فروشگاه به وردپرس وصل شود.

---

## وضعیت امروز

سایت با **داده‌ی دستی** کار می‌کند: محصولات در `src/data` نوشته
شده‌اند و بیلد ایستا روی GitHub Pages منتشر می‌شود.

همه‌ی لایه‌ی اتصال ساخته شده و منتظر سه چیز است:

| لازم است | برای چه | چه کسی می‌دهد |
|---|---|---|
| هاست وردپرس | جایی که ووکامرس نصب شود | شما |
| کلید REST ووکامرس | خواندن کاتالوگ در زمان بیلد | از پیشخوان ووکامرس |
| سرویس پیامک | ارسال رمز یک‌بارمصرف | کاوه‌نگار، ملی‌پیامک یا مشابه |

---

## چرا این معماری

سایت **خروجی ایستا** است و سرور ندارد. این یک محدودیت واقعی است
که کل طراحی را تعیین می‌کند:

> کلید ووکامرس اجازه‌ی خواندن سفارش‌ها و مشتری‌ها را می‌دهد.
> اگر در مرورگر باشد، هر بازدیدکننده‌ای می‌تواند بخواندش.

پس کاتالوگ **در زمان بیلد** خوانده می‌شود، نه در مرورگر:

```
npm run sync     ← کلید فقط این‌جا لازم است، روی ماشین شما
   ↓
src/data/generated/catalog.json
   ↓
npm run build    ← سایت ایستا از همین فایل ساخته می‌شود
```

کارهایی که باید زنده باشند — رمز یک‌بارمصرف و ثبت سفارش — از
اندپوینت‌های عمومیِ افزونه می‌گذرند که هیچ رازی ندارند و
اعتبارسنجی‌شان سمت وردپرس است.

---

## گام ۱ — وردپرس و ووکامرس

۱. وردپرس را روی هاست نصب کنید (ایران: لیارا، پارس‌پک، ایران‌سرور).
۲. افزونه‌ی **WooCommerce** را نصب و فعال کنید.
۳. واحد پول را روی **تومان** بگذارید:
   ووکامرس ← تنظیمات ← عمومی ← واحد پول.

> ⚠ اگر واحد را ریال بگذارید، همه‌ی قیمت‌ها ده برابر نشان داده
> می‌شوند. سایت عدد را همان‌طور که می‌گیرد نشان می‌دهد.

---

## گام ۲ — افزونه‌ی پل

پوشه‌ی `wp-plugin/phoenix-bridge` را در
`wp-content/plugins/` آپلود کنید و از پیشخوان فعالش کنید.

این افزونه سه چیز اضافه می‌کند که ووکامرس ندارد:

**تب «فونیکس» روی هر محصول** — نام انگلیسی، برند، روش تحویل،
زمان تحویل، عنوان گارانتی، رنگ شاخص، و فهرست‌های JSON برای
ویژگی‌ها، نکته‌ها، سوالات متداول و ورودی‌های لازم از مشتری.

**انبار کد** — جعبه‌ای پایین صفحه‌ی محصول. هر خط یک کد. موجودی
ووکامرس خودکار برابر تعداد کدهای آزاد می‌شود، و با پرداخت هر
سفارش یک کد برداشته و در یادداشت سفارش به مشتری داده می‌شود.

**فیلدهای پلن** — روی هر واریاسیون: برچسب پلن، مبلغ دلاری، و
راهنمای «این پلن مال کیست».

---

## گام ۳ — کلید و همگام‌سازی

از پیشخوان: **ووکامرس ← تنظیمات ← پیشرفته ← REST API ← افزودن کلید**
با دسترسی **خواندن**.

بعد در ریشه‌ی پروژه فایل `.env.local` بسازید:

```bash
WORDPRESS_URL=https://shop.example.com
WOO_CONSUMER_KEY=ck_xxxxxxxxxxxx
WOO_CONSUMER_SECRET=cs_xxxxxxxxxxxx
```

و همگام کنید:

```bash
npm run sync
```

خروجی می‌گوید چند محصول و چند پلن خوانده شد، و هشدار می‌دهد اگر
محصولی تصویر یا توضیح کوتاه ندارد.

> ⚠ `.env.local` در `.gitignore` است و نباید commit شود.
> اگر کلید اشتباهی commit شد، از پیشخوان ووکامرس **باطلش کنید**؛
> پاک کردن از تاریخچه‌ی گیت کافی نیست.

---

## گام ۴ — سرویس پیامک

بدون این، رمز یک‌بارمصرف ارسال نمی‌شود. در `functions.php` قالب
یا یک افزونه‌ی کوچک:

```php
add_filter('phoenix_send_sms', function ($sent, $phone, $text) {
    // مثال کاوه‌نگار
    $url = 'https://api.kavenegar.com/v1/API_KEY/sms/send.json';
    $res = wp_remote_post($url, array(
        'body' => array(
            'receptor' => $phone,
            'message'  => $text,
            'sender'   => 'YOUR_LINE',
        ),
        'timeout' => 10,
    ));
    return !is_wp_error($res) && wp_remote_retrieve_response_code($res) === 200;
}, 10, 3);
```

در حالت توسعه (`WP_DEBUG` روشن) اگر این فیلتر وصل نباشد، کد در
لاگ وردپرس می‌افتد تا بتوانید تست کنید. در حالت تولید، عمداً
خطای ۵۰۳ برمی‌گردد — تا کسی فکر نکند کار می‌کند در حالی که
پیامکی نمی‌رود.

---

## گام ۵ — اتصال زنده‌ی سفارش

در `.env.local` اضافه کنید:

```bash
NEXT_PUBLIC_BRIDGE_URL=https://shop.example.com
```

این یکی راز نیست و عمداً `NEXT_PUBLIC_` است — فقط آدرس است.

از این لحظه فرم پرداخت می‌تواند:
۱. کد یک‌بارمصرف بگیرد (`/otp/request`)
۲. کد را بررسی کند و ژتون بگیرد (`/otp/verify`)
۳. سفارش ثبت کند (`/order`) و آدرس پرداخت بگیرد

---

## اندپوینت‌ها

| مسیر | روش | دسترسی |
|---|---|---|
| `/wp-json/phoenix/v1/catalog` | GET | عمومی، فقط‌خواندنی |
| `/wp-json/phoenix/v1/otp/request` | POST | عمومی، با سقف نرخ |
| `/wp-json/phoenix/v1/otp/verify` | POST | عمومی، با سقف تلاش |
| `/wp-json/phoenix/v1/order` | POST | نیازمند ژتون |
| `/wp-json/phoenix/v1/customer-by-phone` | GET | کلید ووکامرس |

## قاعده‌های امنیتی که نباید شکسته شوند

**قیمت از کلاینت خوانده نمی‌شود.** سفارش فقط شناسه‌ی محصول و
تعداد می‌فرستد. قیمت را ووکامرس از پایگاه داده برمی‌دارد. اگر
روزی کسی خواست «برای سرعت» قیمت را از سبد بفرستد، همان روز
فروشگاه قابل تقلب می‌شود.

**شماره باید تأیید شده باشد.** اندپوینت سفارش عمومی است؛ بدون
ژتونِ رمز یک‌بارمصرف، هر کسی با شماره‌ی هر کسی سفارش می‌سازد.

**راز با `NEXT_PUBLIC_` نمی‌آید.** هر متغیری با این پیشوند در
باندل مرورگر پخته می‌شود.

**کد یک‌بارمصرف هش‌شده ذخیره می‌شود** و پنج تلاش بیشتر ندارد.

---

## بعد از پرداخت

درگاه پرداخت هنوز وصل نیست. وقتی وصل شد، تنها کاری که لازم است
این است که پس از تأیید، وضعیت سفارش به `processing` برود —
آن‌وقت تحویل خودکار خودش شلیک می‌شود:

- `stock_code` و `stock_account` → کد از انبار برداشته و در
  یادداشت سفارش به مشتری داده می‌شود
- بقیه → یادداشت «تحویل دستی لازم است» و ستون «تحویل» در فهرست
  سفارش‌ها زرد می‌ماند

هر سفارش فقط یک بار تحویل می‌شود، حتی اگر وضعیتش چند بار عوض شود.

---

## کارهایی که هنوز مانده

- درگاه پرداخت ایرانی (زرین‌پال، آیدی‌پی، …)
- انتقال فرم پرداخت سایت به این اندپوینت‌ها
- شماره‌ی مجازی: هنوز داده‌ی محلی است و به ووکامرس نرفته
- باشگاه مشتریان: امتیاز و کش‌بک هنوز شبیه‌سازی است
